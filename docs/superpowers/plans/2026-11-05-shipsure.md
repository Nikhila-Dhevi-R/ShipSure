# ShipSure implementation plan

This plan implements ShipSure from the supplied DeployDoctor brief under its approved new name. The product is a local-first, evidence-based deployment diagnosis tool distributed as a Python package, standalone CLI, MCP server, and portable Agent Skill compatible with Codex and Claude Code. This plan follows the latest user instruction to implement end-to-end; it does not pause for staged approval.

## Architecture and contracts

- Python 3.11+ package under `src/shipsure`; Python 3.14 is the available local runtime.
- A shared Pydantic-backed domain model and deterministic rule engine consume normalized project facts, logs, and provider observations and emit ranked diagnoses, supporting evidence, uncertainty, safe proposed fixes, verification plans, and structured reports.
- Local project inspection is bounded to an explicit root, skips VCS/build/dependency/secret files, masks sensitive strings, and never executes repository code during diagnosis.
- Provider adapters are read-only: Vercel reads deployment metadata/events/logs and environment-variable names/metadata only; AWS reads EC2/ECS/Lambda/CloudWatch/IAM/deployment configuration using explicit allowlisted API operations. No secret decryption, mutation, redeployment, or policy simulation by default.
- Applying local diffs requires an explicit CLI/MCP call plus expected-content checks and backups. Verification commands use an explicit allowlist / command approval and return observed process evidence; no successful status is inferred from a recommendation.
- Typer CLI, official MCP Python SDK (stdio by default; optional HTTP transport), Codex and Claude clients call the same public service layer. A canonical `skills/shipsure/SKILL.md` is installed into `.agents/skills/shipsure/` and `.claude/skills/shipsure/` by an idempotent helper.
- Optional provider dependencies stay in extras. Core diagnosis and fixture tests work offline. Reports have JSON and Markdown encoders.

## Implementation tasks

### 1. Package, domain model, and safety primitives

Files: `pyproject.toml`, `src/shipsure/models.py`, `src/shipsure/security.py`, `src/shipsure/__init__.py`.

Define validated project context, evidence, diagnoses, recommendations, proposed file changes, verification steps/results, and diagnostic report models. Add deterministic redaction and safe path containment. Tests cover validation, secret masking, path traversal, and report serialization.

### 2. Local project inspection and evidence-backed rules

Files: `src/shipsure/inspectors/`, `src/shipsure/parsers/`, `src/shipsure/rules/`, `src/shipsure/engine.py`.

Collect bounded facts from Python/FastAPI manifests and startup files, Node/React/Vite manifests/configuration, Docker/Compose, GitHub Actions, and Vercel project config. Parse common Python, Node, Docker, GitHub Actions, Vercel, and AWS deployment log signatures. Correlate rule matches with project facts; rank deterministically from explicit evidence strength, specificity, and corroboration. Include alternatives when the log is ambiguous. Add a minimum of 25 realistic fixture-driven scenarios, including cross-platform correlations and false-positive cases.

### 3. Shared diagnosis, reports, fixes, and verification services

Files: `src/shipsure/services/`, `src/shipsure/reporting/`.

Expose stable service functions for diagnose, report, suggest/apply a safe file change, and verification. Produce guarded unified diffs and refuse changed-on-disk files. Verify commands only after explicit user selection/approval, in the chosen project directory, with timeouts and redacted output. Local verification and deployment verification are distinct statuses. Test state transitions and refusal paths.

### 4. Vercel and AWS read-only provider adapters

Files: `src/shipsure/adapters/vercel.py`, `src/shipsure/adapters/aws.py`.

Vercel: Bearer-authenticated bounded REST requests for deployments, deployment events/logs and runtime log records where API permits, plus environment metadata without decrypted values; redact all returned text. AWS: optional boto3 session/profile/region; bounded paginators; inspect EC2 status, ECS service/task events and deployments, Lambda configuration/recent errors, CloudWatch log events, IAM role/policy metadata and relevant deployment configuration. Every operation is read-only; calls are bounded by region, resource identifier, time range, and result caps. API permission failures become explicit actionable evidence; no credentials are collected or printed. Use short SDK timeouts and standard retries.

### 5. CLI and MCP interfaces

Files: `src/shipsure/cli.py`, `src/shipsure/mcp_server.py`.

CLI commands: `diagnose`, `logs`, `inspect`, `report`, `fix preview/apply`, `verify`, `vercel`, and `aws`. MCP tools map to shared service functions, use typed schemas, read-only annotations for diagnosis/provider calls, and mutation annotations plus explicit expected-content checks for local apply. Stdio is default; network transport is explicit opt-in. Tests exercise CLI and MCP service contracts without requiring external accounts.

### 6. Agent Skills, packaging, docs, examples, CI, contribution setup

Files: canonical portable skill and two client skill directories, installer script, README, security model, supported checks reference, examples/fixtures, `.github/workflows/ci.yml`, license, contribution guide.

Document Python/Codex/Claude/MCP installation, provider permissions, threat model, exact supported checks, environment configuration, safe repair and verification behavior, JSON/Markdown examples, extension interfaces, test commands, and known limitations. Add CI across supported Python versions and operating systems where possible. Keep skill instructions explicit that tools gather evidence and the model must not assert unobserved fixes.

## Verification

- Use standard-library `unittest` for core local offline tests and expose compatibility with pytest.
- Add fixture-based tests for at least 25 deployment failures across Python/FastAPI, Node/React/Vite, Docker, GitHub Actions, Vercel, and AWS.
- Cover redaction, path traversal, malformed/untrusted logs, bounded input/output, provider read-only operation allowlists, timeouts, permissions failures, fix preview/apply conflict handling, verification failure/success status, MCP schema, CLI output, and report round-trips.
- Run the full suite, package build/install, CLI smoke checks, MCP initialization/tool-list check, lint/type checks if available without adding unneeded tooling, and `git diff --check`. Report any external-client/live-cloud limitations honestly.

## Acceptance criteria

- One shared deterministic engine powers CLI, MCP, and skills.
- The required integrations produce concrete findings from either local evidence/fixtures or bounded read-only live provider data; no provider capability is represented as live if it is only a local log rule.
- Findings cite source evidence, calibrated support strength, alternatives, and safe action/verification guidance.
- No default command mutates files, runs repository scripts, decrypts provider secrets, or changes external infrastructure.
- Explicit local fix application is previewable, reversible, and guarded against concurrent changes; execution-backed verification is the only path to verified labels.
- Documentation, test scenarios, and install instructions match the implementation.
